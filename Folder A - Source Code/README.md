# Folder A – Source Code

## 1. Overview

This folder contains the software, control logic, simulation files, flowcharts, and testing documentation for the **Solaform Artificial Leaf** prototype.

The control system is based on an **Arduino microcontroller** and is designed to monitor system conditions, control the different operating stages, provide system-status information, and initiate safe shutdown conditions when required.

The software supports the overall Solaform process:

```text
SOLAR ENERGY
     ↓
CO₂ CAPTURE
     ↓
CO₂ REGENERATION
     ↓
ELECTROCHEMICAL CONVERSION
     ↓
FORMATE + O₂
     ↓
MONITORING / OUTPUT
```

## 2. Control System

The Arduino controller coordinates the prototype's electronic components and operating states.

The control system is responsible for:

* Reading sensor inputs.
* Monitoring temperature.
* Monitoring CO₂-related parameters.
* Monitoring system operating conditions.
* Controlling indicators and actuators.
* Displaying system status on the OLED display.
* Managing the capture, regeneration, and conversion stages.
* Detecting predefined abnormal conditions.
* Initiating appropriate shutdown actions.
* Providing feedback to the user during system operation.


## 3. Main Operating States

The prototype control logic is organised into three primary process states.

### CAPTURE

During the capture stage, the system receives the controlled CO₂ input and prepares the capture section for CO₂ collection.

The system monitors the relevant operating conditions and indicates that the capture stage is active.

**Indicator:** Green LED


### REGENERATION

During regeneration, the captured CO₂ is released from the capture medium under controlled conditions.

Temperature monitoring is used to control and verify the regeneration stage.

In the prototype simulation, the regeneration stage is completed when the simulated regeneration temperature reaches the predefined operating threshold.

**Indicator:** Red LED


### CONVERSION

During conversion, the regenerated CO₂ is directed toward the electrochemical conversion section.

The electrochemical system is intended to reduce CO₂ toward formate while water oxidation produces oxygen.

**Indicator:** Blue LED

The conversion stage represents the core artificial-leaf function of the Solaform concept.

### Inputs

### Outputs

* OLED display.
* Warning indicators.
* Other actuators required by the final prototype.

## 5. Solar-Energy Control Concept

The full Solaform system is designed around a solar-energy supply architecture.

```text
SUNLIGHT
   ↓
SOLAR PANEL
   ↓
CHARGE CONTROLLER
   ↓
RECHARGEABLE BATTERY
   ↓
POWER MANAGEMENT / DISTRIBUTION
   ↓
SYSTEM LOADS
```

The solar panel provides the primary renewable-energy input.

The rechargeable battery stores electrical energy generated by the solar panel and provides a more stable electrical supply to the system when solar intensity changes.

The power-management section distributes the stored electrical energy to the appropriate system components.

A controlled DC power supply may be used during laboratory testing and prototype development where necessary.


## 6. Wokwi Simulation

The Solaform Arduino control concept is also developed and tested using **Wokwi** simulation.

The simulation is used to:

* Test the control sequence.
* Test sensor inputs.
* Simulate changing operating conditions.
* Test the OLED display.
* Test LED indicators.
* Test the servo motor.
* Test temperature-based regeneration control.
* Identify software and logic errors before physical implementation.

The Wokwi simulation represents the control logic of the physical prototype and may not reproduce the complete physical electrochemical process.

## 8. Safety-Related Software Logic

The software is designed to support the physical safety system but does **not replace the physical Emergency Stop circuit**.

Where applicable, the software will:

* Monitor temperature limits.
* Detect abnormal sensor conditions.
* Display warning messages.
* Stop selected actuators when unsafe conditions are detected.
* Prevent selected process stages from operating when required conditions are not met.
* Return the system to a safe state when a software-detected fault occurs.

The physical Emergency Stop is designed to interrupt power to hazardous or active loads independently of normal software operation.
